KSD Dispatch + Orbit

From request to receipt.

Dispatch governs execution and mission state. Workers perform bounded work. Orbit independently verifies the evidence. A worker cannot certify itself complete, and Orbit cannot rewrite Dispatch state.

01IntentA person states the outcome in normal language.
02AuthorityDispatch checks scope, permission and required approval.
03AssignmentA bounded, eligible worker receives the mission.
04ExecutionThe worker acts within the admitted scope.
05VerificationOrbit checks the evidence independently.
06ReceiptDispatch accepts only the state transition supported by the required proof.
Where Workspace fits

The interface is not the authority.

KSD Workspace is where a person sees work, opens rooms, reviews context, communicates and approves bounded actions. When execution is requested, Workspace hands the governed request to Dispatch rather than becoming Dispatch itself.

Dispatch

Sole governed execution control plane.

Dispatch owns mission assignment, authority, state transitions and closure. Scheduler, workers, managers and providers can contribute, but they do not become Dispatch.

Orbit

Independent verification and supervision.

Orbit checks whether the evidence supports the claim, looks for alternatives when execution repeatedly fails, and cannot mutate Dispatch state or self-approve the work it did not execute.

Proof discipline

A green check is not enough.

KSD distinguishes source completion, real execution, retained evidence, independent verification, human acceptance where required, and release authorization.

Bounded executionWorkers receive explicit authority rather than unrestricted access.
Attributable receiptsEvidence is tied to the mission and executor that produced it.
Fail closedMissing authority, proof or required human action blocks completion.
Forward repairEligible failures can produce a materially different corrective path with a new proof gate.
